# 项目经历

## 质量管理系统 · 研发风险

2025.01 — 至今 · 模块主要开发

Vue 3 · TypeScript · Vite · Naive UI · Pinia · i18next

手机制造质量管理平台中的研发风险流程。用户从风险提报、收集、识别走到评审和任务处理，不同流程节点上，同一张表里能改的字段不一样。系统是微前端，我的工作在业务子应用里。

- 按流程节点和当前处理人控制字段可编辑或只读。页面只读时不挂校验规则，避免按钮隐藏以后，单元格和必填校验还在生效。
- 驳回给发起人时恢复基本信息的必填；完成情况是否可编辑按节点单独判断，不和普通审批共用一套规则。
- 列表筛选和提交使用字典编码，页面只显示文案，避免用中文去比对接口数据导致筛选为空。
- 导出时去掉未选择的筛选条件。日期禁止选今天之前，当天可选，计划的开始和结束可以是同一天。
- 新建和审批拆成不同页面，附件和基本信息拆成子组件。重复发起评审时，接口返回已存在则直接打开查看页。
- 同一时期还负责质量检验里的主要页面，包括检验结论切换时清空残留值，以及自动带出的结论不允许手改。
- 封装字典树选择、级联选择、表格工具栏和带编辑弹窗的输入框，并维护工厂与供应商的选择弹窗。附件上传由我后期主要修改。
- 调整本地联调的启动方式和端口。外部系统嵌入时隐藏侧边栏，首页增加意见反馈入口，并调整语言编码和按钮权限的挂载位置。
